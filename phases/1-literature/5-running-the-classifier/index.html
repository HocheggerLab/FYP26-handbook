    Part 5 · Running the classifier¶

    Goal¶

    Run the Jev classifier over the same 50 abstracts you classified by hand, so that in Part 6 you can measure how well it agreed with you.

    You will learn the tool by interrogating it with the agent, then run it yourself from the terminal. Both halves matter: the agent is there to explain, not to press the button for you.

    Time¶

    About an hour and a half. Evaluation runs happen during 17–24 November, after the independent references are locked.

    Before you start¶

    • Part 4 finished: VS Code, uv and Claude Code working.
    • Your abstract classifications submitted. Do not run the classifier before your own answers are locked. Seeing the model's answers first contaminates the reference you are measuring it against, and there is then nothing left to compare.
    • The .env file your supervisor sent you by Slack DM.

    Steps¶

    1. Get the tools¶

    git clone https://github.com/Helfrid/fyp26-tools
cd fyp26-tools
uv sync --all-packages

    This folder holds the scanner, the 250 abstracts assigned across the group (input_data/), and everyone's hand classifications (abstracts_annotated/).

    2. Put the key in place¶

    Save the .env file your supervisor sent into the fyp26-tools folder.

    Open the file in VS Code and paste the key there yourself

    Do not paste the key into the Claude Code chat, and do not ask the agent to write it for you. Everything typed in a session is written to a transcript file on your computer — including ! shell commands. Putting the key in the editor keeps it out of every transcript.

    Never commit .env, and never paste the key into a notebook or a results file. It is gitignored, and a pre-commit check will refuse a commit that contains it.

    3. Learn what the tool does — with the agent¶

    Start Claude Code in the fyp26-tools folder:

    claude

    Ask it to explain the tool before you run anything. Useful prompts:

    • "Read the README and CLAUDE.md and explain in plain language what this repository does."
    • "What is a question set? Show me question_sets/fyp26_tagging_v3.toml and explain how it relates to the four fields I classified by hand."
    • "What does abstract-scanner guide print, and who is it written for?"
    • "Explain every flag on the scan command. What does --budget do, and what happens when it runs out?"
    • "Where does the output go, and what is the manifest file for?"

    Then ask it to give you the exact terminal commands for the three steps below — and check them against this page before running anything. If the agent's command differs from the one here, this page wins. Ask it why they differ; it is a good test of whether you understand the tool.

    Do not let the agent change the question set

    fyp26_tagging_v3.toml must stay exactly as it is. It encodes the same four fields and the same wording that you classified by hand. If a single instruction is reworded the file's fingerprint changes, your run can no longer be compared with anyone else's, and your result drops out of the group analysis. If the agent offers to improve it, decline.

    4. Check the question set — costs nothing¶

    uv run abstract-scanner validate -q packages/abstract_scanner/question_sets/fyp26_tagging_v3.toml

    You should see four questions and a fingerprint. Note the fingerprint down; it identifies exactly what was asked.

    5. Price the run — costs nothing¶

    uv run abstract-scanner estimate \
  -a input_data/phase1_tagging_abstracts.json \
  -q packages/abstract_scanner/question_sets/fyp26_tagging_v3.toml

    Nothing is sent and nothing is charged. Read the number before you spend it. The whole set of 250 abstracts costs roughly one US cent.

    6. Run the scan¶

    uv run abstract-scanner scan \
  -a input_data/phase1_tagging_abstracts.json \
  -q packages/abstract_scanner/question_sets/fyp26_tagging_v3.toml \
  -o results/jev_tagging_v3.jsonl \
  --budget 0.05 \
  --cache .cache

    What the flags mean:

    Flag Meaning
    -a the abstracts to read in
    -q the questions to ask about each one
    -o where the answers are written out
    --budget a hard spending ceiling in US dollars. Required — there is no default
    --cache remembers answers, so running again costs nothing

    If it stops at the budget it says so, keeps everything it finished, and exits with code 2. Raise --budget and run the identical command again; it picks up where it left off.

    7. Look at what came back¶

    Open results/jev_tagging_v3.jsonl. One line per abstract, each a JSON object with the four answers. For every question you get the chosen option, a confidence, and the full probability distribution across the options — more than you produced by hand, and useful later.

    Open results/jev_tagging_v3.manifest.json too. It records the question fingerprint, the model version, how many abstracts were scanned, the tokens used and the actual cost. Keep the two files together: without the manifest you cannot say what a result file actually is.

    8. Log it¶

    Add a line to ai-use-log.md: what you asked the agent, what it told you, and anything you had to correct. If the agent gave you a command that was wrong or that you chose not to run, that is worth recording — it is evidence of the judgement the project is assessing.

    Done when¶

    • results/jev_tagging_v3.jsonl has one line per abstract.
    • You can explain, without looking it up, what -q, -o and --budget do.
    • You can say what the fingerprint is for, and why the question set must not be edited.
    • ai-use-log.md has an entry.

    If something goes wrong¶

    The classifier fails loudly rather than silently. Read the error, then ask the agent what it means — debugging with the agent is exactly the right use of it.

    What you see Usually means
    no API key: set TYPESAFE_API_KEY .env is missing, in the wrong folder, or the key line is empty
    ✗ every record failed the request was rejected; read the first error printed underneath
    stopped at the budget ceiling not an error. Raise --budget, run the same command again
    no such corpus file you are not in the fyp26-tools folder, or the path is mistyped
